# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers and technical operators who want an AI agent close to their terminal, code, files, browser, and service integrations.

## Product Purpose

HelloChusquis provides a developer-controlled local-first agent for conversation, planning, tool use, memory, code execution, web access, and integrations. Success means users can move from a plain-language request to visible, bounded work without leaving their local workflow.

## Positioning

The product keeps agent activity legible: tools, progress, approvals, memory, and failures remain visible while the agent works beside a terminal or codebase.

## Operating Context

Users run HelloChusquis in the terminal, an authenticated web interface, or through the REST API. The web workspace combines chat, provider/model selection, voice controls, command actions, appearances, approvals, and a local plugin/skill/MCP marketplace.

## Capabilities and Constraints

- Built around local-first use, provider configuration, streaming chat, bounded tool execution, approval gating, isolated sessions, and persistent local memory.
- Integrations are capabilities, not proof of a hosted SaaS experience.
- Preserve existing product copy, routes, controls, and the 33-item local marketplace catalog.
- The primary user may use desktop or mobile web; layouts must adapt without changing functionality.

## Brand Commitments

- Name: HelloChusquis.
- Supplied primary logo is the authoritative brand mark.
- Brand voice is direct, local, technical, practical, and controlled.
- The existing dark amber terminal identity is being replaced for this redesign rather than extended.

## Evidence on Hand

- README.md documents the terminal, web, API, integrations, memory, approvals, and safety model.
- web/index.html is the runnable landing, chat, settings, command palette, and marketplace surface.
- web/assets/logo-primary.png is the supplied primary logo.
- The marketplace catalog is sourced from core/marketplace_catalog.json and currently contains 33 items.

## Product Principles

- Keep automation visible.
- Preserve developer control and recoverability.
- Prefer familiar tools and direct language.
- Make capability dense without making the interface dense.
- Keep local and private behavior prominent.

## Accessibility & Inclusion

- Keyboard navigation and visible focus are required.
- Controls need comfortable pointer and touch targets.
- Text and color must remain legible, with reduced-motion behavior.
- Essential state must not rely on color alone.
